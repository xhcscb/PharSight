# Pharsight GraphRAG V1.2 运行与评测

> 文档用途：复现完整 PDF 构图、检查图质量、评估检索和报告增益
> 数据边界：仅使用项目已批准且满足报告截止时间的来源
> 安全要求：不记录密钥，不提交数据库、索引、日志和生成报告

## 1. 标准运行链路

```text
批准来源/PDF
  → PDF 文本解析或 OCR
  → 页级确定性索引
  → Passage 级结构化抽取
  → Evidence quote gate
  → 实体消歧与角色边
  → 原子记录及材料性写入 SQLite / 基础图投影
  → QueryPlan 与高召回 Claim 候选
  → 基础图 / BM25 扩展
  → 查询相关候选对阻塞、关系判断与临时子图
  → Evidence Pack / ToolResult
  → DataAnalyzer
  → ReportGenerator
  → 引用与来源覆盖检查
```

不得跳过 PDF 解析器让模型直接阅读 PDF。构图输入应是持久化索引中的页级文本块，报告
必须保留 source ID、页码和 chunk ID。

## 2. 构图前检查

1. 确认研究模式、报告截止时间和批准 source ID；
2. 确认每份 PDF 的解析器、文档哈希、页数和文本覆盖；
3. 抽查首页、目录、正文、表格密集页和末页，确认页码没有整体偏移；
4. 确认索引块不跨页，chunk ID、页码和 document hash 稳定；
5. 确认 `DS_MODEL_NAME` 指向本次批准使用的主模型服务；
6. 确认 Graph SQLite 位于 `outputs/.graph_cache/`，不使用历史实验数据库冒充新构建。

扫描 PDF 只有在文本解析不足时才进入 OCR。OCR 内容必须保留解析器标识，并在 Evidence
Pack 的 limitations 中提示质量风险。

## 3. 构图过程监测

### 3.1 必看指标

- Passage 总数、完成数和并发进度；
- 每个 Passage 的有效记录数、Schema 拒绝数、quote 错挂数和抽取失败数；
- Claim/Observation/Event 分布；
- 实体类型分布、temporary/needs_review 比例和高频枢纽；
- 组织边和角色边数量；ingest 后七类持久语义边应为零；
- 材料性四维及总分的分布、极端值和 reason 可解释性；
- 构建耗时、模型调用量、重试次数和失败率；
- BuildReport 与 `build_runs` 的 built/reused/failed 状态是否一致。

### 3.2 失败判断

以下情况不能把文档视为成功完成：

- PDF 没有解析出正文或页码明显错位；
- Passage 抽取失败比例超过配置阈值；
- 全文没有结构化记录且存在抽取失败；
- Evidence quote 无法在 Passage 中定位；
- 数据库出现部分 Document/Passage，而 build run 被错误标记为 built；
- 构图来源越过批准 source ID 或报告截止时间；
- 模型名称、Schema 或抽取器版本没有随构建记录保存。

### 3.3 图规模不能单独代表质量

图大不等于有效。应同时观察：

- 每条 Record 能否回到 Evidence 和 Passage；
- Evidence 是否真的支持 Record 的主体、数值和条件；
- 实体是否过度合并或产生大量同名临时节点；
- 高连接实体是否只是发行人、监管机构等泛实体；
- 关系是否集中在有意义候选中，而不是全库共现；
- 图检索是否召回 BM25 遗漏的目标页。

查询阶段还必须记录：宽候选池大小、目标 Claim Recall@pool、进入关系判断的 Record 数、
阻塞前后候选对数、hard gate 拒绝数、查询边数量与精确率，以及规划/关系两次模型调用的
延迟。边数少可能是严格门控的正确结果，边数多也不能证明关系完整。

## 4. 检索评测设计

### 4.1 固定问题集

评测问题至少覆盖：

- 精确实体和别名；
- 简单财务或临床事实；
- 明确报告期；
- 药物—适应证—试验等多跳问题；
- 状态更新时间线；
- 跨文档比较；
- 冲突、不可比和 supersedes；
- 数量/清单问题；
- 图中无记录但原文存在的回退问题；
- 不在批准来源范围内的拒绝问题。

每题冻结 query、目标 source ID、目标页/块、可接受答案要点和不可遗漏条件。不能在看到某个
后端结果后修改 gold answer。

### 4.2 同预算比较

Chunk、Graph、Hybrid 必须使用相同来源集合、相同 top-k 和相同截止时间。至少记录：

- source Recall@k；
- target page/chunk Recall@k；
- atomic Claim Recall@pool 与 Recall@k；
- Precision@k 或人工相关性；
- 带结构化 Record 的命中数；
- 关系问题中正确关系理由的覆盖率；
- 平均和 P95 延迟；
- 模型规划调用和构图摊销成本；
- BM25 回退率。

GraphRAG 增益应表述为“在相同证据范围和预算下增加了哪些目标证据召回、结构化条件或
关系解释”，不能仅以节点数、边数或报告篇幅作为证明。

### 4.3 报告级评测

检索改善不必然等于报告改善。最终还应比较：

- 关键结论的 citation coverage；
- 引用 source/page/chunk 的可定位率；
- 数值、单位、剂量、报告期和不确定性的保持率；
- 多来源覆盖和单一来源集中度；
- 冲突是否显式披露；
- candidate 记录是否被误写成已确认事实；
- 事实错误、漏引和跨期混用数量；
- 领域审核者对完整性、可比性和投资相关性的评分。

## 5. 2026-10-12 公司模式历史基线

以下数字来自 v1.1“ingest 时全局关系预计算”，用于说明问题和做回归参照，不代表 v1.2
当前架构。v1.2 ingest 预期不创建七类语义边，关系指标必须按每个冻结 query 单独统计。

输入为 `assets/v2_graph/` 中三份完整 PDF，先完成文本解析和页级索引，再使用当前主模型
服务进行 GraphRAG 构建和报告生成。

| 指标 | 结果 |
| --- | ---: |
| PDF / 页数 | 3 / 418 |
| Passage | 449 |
| Evidence | 4,585 |
| Claim/Observation/Event 总记录 | 4,920 |
| Entity | 1,826 |
| 构图边总数 | 17,146 |
| 被阻塞并审核的关系候选对 | 623 |
| 接受的七类语义关系 | 174 |

接受关系分布：89 `INCOMPARABLE_WITH`、72 `SUPPLEMENTS`、9 `EQUIVALENT_TO`、
3 `SUPPORTS`、1 `SUPERSEDES`；没有为了填满图而强制生成其他关系。

冻结的 8 问评测中：

| 后端 | 来源 Top-1 | 目标页 Recall@5 | 带结构记录命中 | 平均延迟 |
| --- | ---: | ---: | ---: | ---: |
| Chunk | 5/8 | 5/8 | 0 | 0.55 s |
| Hybrid | 8/8 | 8/8 | 27 | 2.89 s |

该历史实验可支持的结论是：在该公司模式、该三份 PDF 和该 8 问冻结集合上，Hybrid 修复了
Chunk 对错报告期、跨文档实体串联和结构化关系问题的部分漏召回，并提供了记录、路径和
关系理由。它不能证明所有问题、行业模式或新公司上都优于 Chunk，也不能把 8/8 外推为
事实正确率。

完整流程生成 11 节 Markdown 研报，三份输入来源均被正文引用。该结果证明技术链路闭合，
不等于报告已经通过证券研究或医药领域的人工质量验收。

## 6. 当前残余风险

- 当前机器使用 Python 3.12；仍需在项目标准 Python 3.11 完整复验；
- 行业模式尚未完成等规模真实语料端到端评测；
- 自动记录仍以 candidate 为主，缺少系统化领域双人复核；
- rejected 已在 Claim 候选检索排除；superseded 仍可能用于时间线，必须检查 review status；
- QueryPlan 的记录类型和领域尚未成为硬过滤条件，可能扩大候选范围；
- 查询时关系判断会增加在线主模型延迟；失败时基础 Claim/Chunk 召回仍可用，但必须返回 warning；
- 三份 PDF 均属于受控公司材料，尚未验证监管、试验注册和论文等多来源冲突；
- 逐 Passage 主模型抽取成本较高，尚缺少持久断点续建和完整 token/费用仪表；
- 现有 8 问集合规模小，需要扩展并长期冻结回归集；
- v1.2 查询关系 hard gate 仍需在扩展问题集上抽样检查 precision 和漏边率；
- PDF 表格的线性文本解析可能割裂行列语义，关键财务数字仍需原页复核。

## 7. 发布前验收清单

- [ ] Python 3.11 环境完成目标测试、完整 pytest 和 ruff；
- [ ] 公司与行业模式各有冻结语料和问题集；
- [ ] 随机抽样 Record 的 quote、主体、条件、数值、单位和时间全部可回原文；
- [ ] 实体误合并率和 needs_review 处理达到项目阈值；
- [ ] 七类关系通过领域成员抽样，特别检查 `SUPERSEDES` 与 `CONTRADICTS`；
- [ ] 目标原子 Claim 在宽候选池中的 Recall 达到发布门槛，并报告 candidate pool 消融；
- [ ] Graph/Hybrid 不越过批准来源和截止时间；
- [ ] Chunk/Graph/Hybrid 在同预算下完成检索对照；
- [ ] 报告关键结论完成引用、跨期、单位和冲突核验；
- [ ] 输出、缓存、日志和数据库均未进入 Git；
- [ ] 运行使用的模型标识、Schema、抽取器和文档哈希可追溯。

满足这些条件后，才可以把 GraphRAG 从“已完成技术闭环”提升为“经过项目质量验收”。
