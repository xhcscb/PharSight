# Pharsight GraphRAG V1.2 主要更新介绍

> 文档定位：面向项目汇报、架构评审和实验设计的版本更新摘要  
> 当前版本：`pharsight-graph-v1.1` / `graphrag-v1.2`  
> 更新日期：2026-10-18  
> 适用模式：`pharma_company`、`pharma_industry`

## 1. 本次更新解决什么问题

V1.1 在文档 ingest 阶段抽取 Claim、Observation、Event 后，立即在全库候选记录之间预计算
七类语义关系。真实 PDF 审计表明，这种方式容易被共同公司、共同主题、相同 quote 和简单
时间先后误导。关系一旦持久化，又会在后续所有问题中反复参与遍历，即使它与当前问题并
不相关。

同时，原检索路径偏重预先构建的图连接。若相关 Claim 没有被实体角色索引覆盖、没有进入
有限图种子，或者同一来源被固定三条上限提前截断，后续图扩展无法恢复这些漏召回记录。

V1.2 因此把核心问题重新拆分为两个阶段：

1. 离线阶段忠实、稳定地保存原子记录及其证据；
2. 在线阶段围绕具体 query 高召回相关记录，再构建只服务于该问题的关系子图。

## 2. 架构变化概览

```text
V1.1
PDF → Passage → 原子记录 → 全局关系预计算 → 持久化完整语义图 → Query 图遍历

V1.2
PDF → Passage → 原子记录 + 材料性 + Evidence/Entity 基础图
                                      ↓
Query → 高召回 QueryPlan → 宽 Claim 候选池 → 基础图/BM25 补充召回
                                      ↓
                         候选对阻塞 → 查询时关系判断
                                      ↓
                         临时查询子图 → Evidence Pack
```

最重要的变化不是增加一种边，而是重新定义边的生命周期：Document、Passage、Evidence、
Record 和 Entity 构成可持久化基础图；七类记录间证据关系成为 query-scoped projection，默认
不写回权威数据库。

## 3. 更新一：离线只抽取可核验的原子记录

ingest 阶段继续使用 PDF 解析器取得分页文本，模型不直接阅读 PDF。每个 Passage 中的内容
被拆成 Claim、Observation 或 Event，并必须连接到可在原文中精确定位的 Evidence quote。

V1.2 不再在 `GraphBuilder.build_document()` 完成后自动执行全库关系预计算。构建成功只表示：

- 文档、页码和 chunk 身份已经固定；
- 原子记录通过 Schema 和 Evidence gate；
- 记录条件、数值、单位、时间和不确定性得到保留；
- 实体及记录—实体语义角色已经建立；
- 基础图可以由 SQLite 重建为 NetworkX 投影。

它不表示模型已经证明记录之间存在支持、矛盾、等价或替代关系。

## 4. 更新二：为每条记录增加材料性评分

每条原子记录新增 query-independent 的 `materiality`。它描述记录本身对投研工作的潜在重要
程度，而不是该记录与某个临时问题的相似度。

| 维度 | 权重 | 含义 |
| --- | ---: | --- |
| `decision_impact` | 35% | 是否可能改变公司、产品、行业或风险判断 |
| `evidence_strength` | 25% | 来源陈述是否直接、明确并有充分原文支持 |
| `novelty` | 20% | 是否提供相对已有记录的新信息 |
| `time_sensitivity` | 20% | 是否具有催化剂、更新、失效或披露时效 |

模型输出四个维度、材料性范围和理由；总分由程序确定性计算，避免模型同时控制维度和最终
权重。范围包括 company、product、trial、market、policy、accounting 和 other。

材料性只用于同等相关候选之间的轻量加权。低材料性记录不会被硬过滤，因为背景条件、反证
和限制性说明可能正是当前问题所需要的内容。

## 5. 更新三：QueryPlan 由保守命中改为高召回规划

查询规划明确以 recall 为第一目标。除问题中的直接词语外，计划还应覆盖：

- 公司、药物、项目、试验和适应证的中英文名称；
- 研发代号、证券简称、常见缩写和别名；
- 财务、临床、监管表格中可能出现的表头术语；
- 需要的记录类型、领域、时间范围和关系类型。

规划失败或超时时仍保留确定性中文 n-gram、英文 token 和 BM25 回退，不让一次模型规划失败
导致整个检索路径为空。

## 6. 更新四：建立宽原子记录候选池

V1.2 在关系判断之前，先直接搜索所有未被 rejected 的原子记录。默认候选池为 120 条，检索
范围包括：

- Record 原始陈述文本；
- 结构化 attributes；
- Evidence quote；
- Passage 章节标题；
- 从全部记录—实体边派生的规范实体名称。

该路径不再依赖可能不完整的 `record_entities` 辅助索引。记录类型、领域和材料性均作为软
加权信号，source ID、document hash 和批准来源集合则作为硬边界。

检索同时保留基础图有限跳扩展和 Passage BM25。三路结果在 Evidence/Passage 层合并，既
利用结构化 Claim，又保留图尚未覆盖的表格和上下文。

## 7. 更新五：查询时构建关系子图

Retriever 从本次问题的高分记录中最多选择 24 条进入关系阶段。它不执行 N² 全比较，而是
只有满足以下至少一个条件的记录对才进入模型判断：

- 共享规范实体；
- 具有相同 object、subject、metric、event_type 或 predicate；
- 来自同一 Evidence span。

每次 query 最多提交 100 个候选对。模型只能输出以下七类关系：

- `EQUIVALENT_TO`
- `SUPPORTS`
- `SUPPLEMENTS`
- `INCOMPARABLE_WITH`
- `CONTRADICTS`
- `SUPERSEDES`
- `SAME_ORIGIN_AS`

每条接受边返回左右记录、方向、置信度、理由、可比性、query relevance、模型标识、审核
状态和 `origin=query_time`。这些边随 Evidence Pack 返回，不默认进入 SQLite 权威图。

## 8. 更新六：模型判定之后增加确定性 hard gate

模型输出不是最终连边决定。V1.2 在 Schema 校验和 0.8 置信阈值之后继续执行关系专属规则：

| 关系 | 最低确定性条件 |
| --- | --- |
| `SAME_ORIGIN_AS` | 同 source 且同 Evidence ID |
| `EQUIVALENT_TO` | object、metric、value 一致，且已知条件、单位、时间点和报告期不冲突 |
| `SUPERSEDES` | 存在更新、更正、撤回、替代、终止或修订等明示信号，并有稳定主体 |
| `SUPPORTS` | 至少共享实体；普通 Event→Event 时间先后不能视为支持 |
| `CONTRADICTS` | query 有比较意图，且共享 metric、event_type 或 predicate |
| `INCOMPARABLE_WITH` | query 有比较意图，且两侧至少共享实体或关键语义维度 |
| `SUPPLEMENTS` | 至少共享实体、object 或 subject |

这些规则重点防止 V1.1 已观察到的误差：同 quote 被误写为等价、后发生事件被误写为替代、
共同公司被误写为支持，以及完全无关记录被大量标为不可比。

## 9. 更新七：隔离历史错误边并改善最终排序

基础图遍历只使用组织边和记录—实体角色边。旧数据库中可能残留的七类持久语义边不参与
种子扩展，也不提供关系理由；当前 query 产生的临时边才是该问题的关系依据。

最终排序综合以下信号：

- 查询词与实体/记录/原文的匹配；
- Claim 直接检索、基础图和 BM25 的多通道命中；
- 报告期和显式来源匹配；
- 审核状态与轻量材料性先验；
- 查询边置信度和路径长度；
- 来源多样性。

单来源查询允许返回完整 `top_k`，不再固定最多三条；多来源查询使用自适应来源上限，兼顾
召回与来源集中度。

## 10. Evidence Pack 的变化

原有命中继续返回原文、页码、chunk ID、source ID、结构化记录、图路径和关系理由。V1.2
新增顶层 `query_edges`，使 DataAnalyzer 和质量检查能够区分：

- 哪些是持久化基础图事实；
- 哪些是本次查询产生的模型关系判断；
- 每条关系为什么被接受；
- 哪些关系仍处于 candidate 状态。

报告生成器仍不直接访问 SQLite 或 NetworkX。所有最终结论必须回到 Evidence/Passage，查询
边只能帮助组织和解释证据，不能独立成为事实来源。

## 11. 预期收益

本次更新预期带来四类收益：

1. **提高相关 Claim 的召回。** 先宽检索记录，再连边，避免静态图缺边直接造成不可恢复的
   漏召回。
2. **降低关系误判的传播范围。** 错误边即使出现，也只影响当前 query，不会永久污染所有
   后续问题。
3. **让重要性与相关性分离。** 材料性描述记录的投研价值，查询分数描述当前问题相关度，
   两者不再混为一个不可解释分数。
4. **改善审计能力。** 每条查询边携带理由、可比性、模型和状态，可以单独评测关系质量。

这些是架构预期，不等于已经证明报告质量提升。收益必须通过冻结语料和对照实验验证。

## 12. 下一轮实验必须回答的问题

V1.2 不能只比较最终答案，需要分层评测：

### 12.1 原子记录层

- 关键页面是否抽取出全部必要 Claim/Observation/Event；
- 原文蕴含、数值、单位、时间、条件和不确定性是否保持；
- 材料性四维是否稳定、可解释，是否对不同领域产生系统性偏差。

### 12.2 候选召回层

- gold Claim Recall@20、Recall@50、Recall@120；
- 别名扩展、attributes、quote、section、entity 各通道的消融结果；
- 候选池扩大后 precision、延迟和关系调用成本的变化；
- PDF 中零 Record 页面和表格线性化对召回的影响。

### 12.3 关系层

- 七类边分别统计 precision、recall、F1，而不是只报告边总数；
- 特别审计 `SUPERSEDES`、`CONTRADICTS` 和 `EQUIVALENT_TO`；
- 统计候选阻塞漏边率和 hard gate 错拒率；
- 比较静态全局关系与 query-scoped 关系的错误传播差异。

### 12.4 报告层

- 关键结论引用覆盖率和目标页召回；
- 多来源覆盖、冲突披露、跨期混用和单位错误；
- 相同上下文预算下 Chunk、V1.1 Hybrid 与 V1.2 Hybrid 的报告质量差异；
- 查询规划和关系判断增加的平均/P95 延迟及模型费用。

## 13. 当前边界与后续工作

- 当前记录召回仍以可解释词法和结构字段为主，没有引入新的 embedding 服务；
- QueryPlan 别名扩展依赖主模型，仍需受审实体别名库补强；
- PDF 表格解析质量决定原子记录上限，图无法恢复未被正确解析或抽取的内容；
- 查询边默认是 candidate，在达到领域抽样精确率门槛前只用于导航和证据组织；
- 2026-10-12 的 418 页结果属于 V1.1 历史基线，必须使用 V1.2 重新构图和评测；
- Python 3.11、行业模式和领域人工复核仍是发布前必需项。
