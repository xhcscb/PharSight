# 完整 PDF 分页检索与医药研报验收记录

## 1. 结论

2026-09-22，Pharsight 首次跑通以下真实技术闭环：

```text
发行人托管的公开 PDF
  → PaddleOCR 整本解析与缓存
  → 按页确定性分块并持久索引
  → 七类研究任务分别检索
  → 页码与 chunk_id 随证据进入 Memory
  → DataAnalyzer 分析
  → ReportGenerator 生成 11 节中文公司研报
  → 精确引用校验与参考资料渲染
```

本次样例是一份 189 页的恒瑞医药年报，形成 489 个文本块。V3 最终 Markdown 报告成功落盘，11 个模板章节均非空、正文完整闭合，运行日志以 `All tasks completed` 结束。该结果证明“完整 PDF 不漏页地进入可检索索引，并按任务向现有 FinSight 主流程供证”可运行；它不证明单份年报足以支撑完整医药投研结论，也不等同于领域质量验收。

## 3. 实现方法

### 3.1 整本只解析一次

`PaddleOCR PDF reader` 始终请求完整文档并缓存完整返回。`max_pages` 只裁剪返回给调用者的预览，不改变远程解析范围，也不改变索引范围。这样可避免智能体在不同任务中用不同页数参数重复提交同一 PDF、增加费用或产生不一致版本。

缓存及索引都写入被忽略的 `outputs/.document_cache/`。缓存键基于源 URL；索引身份进一步包含完整文档内容哈希。

### 3.2 分页与分块

索引器接受完整页面数组，并按页生成确定性文本块：

- 默认块长 1,800 字符，重叠 240 字符；
- 一个块绝不跨越页面边界；
- 每块保留 `document_hash`、`chunk_id`、页码、页内块序号、章节标题、文本哈希、来源 URL、父来源编号、解析器和获取时间；
- `chunk_id` 由文档身份、页码和页内序号组成，可稳定去重和回查；
- 索引清单记录总页数和总块数，调用者不必把整本 OCR 文本放进提示词。

### 3.3 按任务检索

新增 `PDF evidence search` 工具。调用参数以具体研究问题为核心，可选限定父文档来源编号，并控制 `top_k`。当前后端使用确定性的 BM25 风格词法评分，补充少量医药同义查询扩展、精确短语加分和单页命中上限。

返回结果以父文档为单位，包含：

```text
source_id
document_hash
query
retrieval_hits[]:
  chunk_id
  page_start / page_end
  section_title
  text
  score
```

本轮任务命中了年报前部业务与研发信息，也命中了后部审计及财务附注，覆盖页码包括第 5、11–13、20、30–32、36、38–40、43–45、61–63、71、80、104–105 及 140–181 页。这证明检索不再受“只解析前若干页”限制。

### 3.4 Memory 合并

首次解析只向 Memory 写入文档索引摘要，不注入整本文本。后续每次任务检索将命中块合并到同一父文档证据记录：

- 以 `source_id` 找到父文档；
- 以 `chunk_id` 去重；
- 保留所有已批准命中的页码定位；
- 更新 `approved_evidence`，供分析和写作使用；
- 报告引用父 `source_id`，事实定位使用页码和块号。

这一边界避免为同一 PDF 的每个块创建不同参考资料编号，也为后续 Claim–Evidence 图保留稳定节点身份。

### 3.5 引用失败关闭

报告只允许引用本轮 Memory 中存在的完整来源编号。中文模型有时会输出 `[来源：WEB-*]`、`来源：`WEB-*`` 或 `来源：[`WEB-*`]`。系统仅对本轮允许集合中的精确完整编号做确定性格式归一化，再执行未知编号校验；模糊名称、截断编号和未知编号不会被猜测或自动匹配。

## 4. 实跑过程与故障修复

### 4.1 首次完整执行

本轮配置包含七个任务级采集问题和五个分析任务，报告使用公司模式完整大纲。初次运行日志显示完成全部 11 个写作章节，但产物复核发现部分章节停在半句、工具调用或空正文；此外，最终引用阶段曾因模型把完整 `WEB-*` 编号包进中文标签或行内代码而被严格校验阻断。这证明只看任务完成日志不足以验收长报告。

### 4.2 修复与断点恢复

修复遵循以下约束：

- 只归一化允许集合里的精确来源编号；
- 不做模糊匹配；
- 未知编号继续失败关闭；
- 增加中文标签、方括号、闭合及未闭合反引号的回归测试。

引用格式修复后，系统又增加章节完整性门槛：草稿必须带显式完成标记、达到最小长度、无残留动作协议、代码围栏闭合，且不能以半句或半表格结束；失败自动重试，仍失败则阻断报告。润色稿执行相同检查，若润色不完整则保留已经验证的草稿。V3 从新目录重跑，11 个模板章节全部通过，引用编排和 Markdown 渲染完成，日志最终记录 `All tasks completed`。

## 7. 对后续图改造的接口

当前实现没有引入图数据库，也没有改变 FinSight 编排。后续图改造应把现有文档索引视为稳定入口，而不是重新解析 PDF：

1. `Document` 节点使用 `document_hash` 和父 `source_id`；
2. `Page`/`Chunk` 节点使用页码和 `chunk_id`；
3. 信息抽取生成 `Entity`、`Event`、`Claim`；
4. `Claim -[SUPPORTED_BY/CONTRADICTED_BY]-> Chunk` 保留原文片段和页码；
5. Graph/Vector/Hybrid 后端仍返回与当前 `retrieval_hits` 兼容的证据字段；
6. ReportGenerator 继续引用父来源编号，不感知底层是词法、向量还是图检索。

切换后端前必须建立固定查询集，对比 Recall@K、页码定位正确率、重复率、跨表/跨页召回、引用完整率、延迟和成本。没有对照评测时，不以“图更先进”为理由替换当前可解释基线。

## 8. 已知限制与下一步

### 8.1 当前限制

- 单份发行人年报不能独立证明临床终点、登记状态、监管审批、医保支付、外部竞争和实时市场价格；
- OCR 对繁体中文、复杂表格、脚注和跨页表格可能产生错字或结构丢失，重大事实必须回看原 PDF；
- 词法检索对同义词、缩写、实体别名和隐含关系的召回有限；
- 多次任务命中会扩大 Memory 与检查点，本轮 V3 的 Memory 约 6.5 MB；
- 最终报告虽有完整章节结构，但证据不足处主要是框架、假设或待补材料，不能视为可发布证券研报；
- 本轮 URL 位于投资者关系托管域，发行人归属和披露等级仍应由人工确认。

### 8.2 下一步优先级

1. 在 Python 3.11 干净环境复现本轮测试和完整报告；
2. 为同一公司加入交易所公告、CDE/NMPA、ClinicalTrials.gov、同行评审文献、医保/集采和行情估值来源；
3. 建立固定问题—相关页标注集，量化当前词法检索的召回和定位准确率；
4. 增加章节级证据预算与惰性块读取，控制 Memory 体积；
5. 在相同证据契约上实现向量、Claim–Evidence 图及 Hybrid 对照；
6. 由医药与证券研究人员逐条复核事实、计算、假设、模型判断和声明。
