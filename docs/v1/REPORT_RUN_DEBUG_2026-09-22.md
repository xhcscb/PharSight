## 发现的问题与处理

### 1. 模型动作协议不兼容

DeepSeek 可能返回 DSML、混合 XML、Markdown 代码围栏、`Python 代码` 标签，或把代码放在空的
`<execute></execute>` 后。原解析器会把这些内容误判为最终答案或无效 Python。

已处理：统一兼容上述格式；空模型响应改为可重试动作；同一响应最后出现 `report`、`outline` 或
`final_result` 时，以最后的终止动作优先，并加入解析回归测试。

### 2. 异步客户端跨事件循环复用

父采集智能体与嵌套 Deep Search 共享异步 LLM 客户端时出现“绑定到不同事件循环”。

已处理：配置对象提供 LLM 工厂，每个智能体创建隔离客户端；异步桥超时取消 future，避免父任务结束后
嵌套搜索继续修改 Memory。

### 3. 同一 PDF 被重复提交 OCR

首次调用超时后，智能体可能改变 `max_pages` 再次提交同一 URL。远程服务实际解析完整文件，页数限制只应
作用于返回切片。

已处理：缓存完整结果及待处理任务 ID；超时后续查同一任务；不同 `max_pages` 复用同一完整缓存；提示词禁止
通过改变页数重复提交。

### 4. 直接 OCR 结果未进入引用证据链

旧路径只有 Deep Search 的 Click 会生成 `WEB-*`。更隐蔽的问题是 BaseAgent 返回工具数据字典列表，旧代码却
按 `ToolResult` 对象读取，导致真实运行中的规范化静默跳过。

已处理：DataCollector 兼容真实返回形态，对远程 PaddleOCR 成功结果自动生成证据并加入允许引用集合，同时
保留文档身份元数据。

### 5. 搜索结果页附件无法继续访问

结果页中的 PDF 直链不在原始搜索白名单，Click 会拒绝，模型随后可能猜测不存在的本地清单或误选材料。

已处理：页面抓取层确定性提取附件并登记到白名单；把精确 URL 和文档类型提示返回给搜索智能体。相对 URL、
绝对 URL、重复链接和无关文件均有单元测试。

### 6. 业绩材料与年度报告容易混淆

仅凭 URL 或模型判断会把业绩推介材料当成年报，报告期也可能错误。

已处理：下载后依据标题、文件名和正文信号分类，并支持调用方声明期望类型；不匹配时不进入 OCR。分类结果写入
证据元数据。发布者归属和来源等级仍需进一步确定性校验。

### 7. 调试大纲被模型扩展

三章节模板经过上游“生成详细大纲”步骤后变成 13 章，既增加成本，也偏离最小闭环验收边界。

已处理：新增 `use_outline_template_directly` 配置；调试配置直接使用已审核模板。默认行为保持不变，不修改运行时
公共 API。

### 8. 模型重编号或本地化来源编号

模型曾把真实 `WEB-*` 重编号为 `S001`～`S004`；后续运行又生成 `[来源: WEB-*]`。前者没有可靠映射，后者只是
同一已知来源的本地化写法。

已处理：提示词只列允许的完整来源编号并禁止别名；确定性后处理仅归一化允许集合中的精确本地化编号；未知编号、
无法证明的 `Sxxx` 和无参考文献映射的编号继续失败关闭。摘要与正文使用同一处理链。

### 9. Windows 控制台编码导致日志噪声

包含 Unicode 符号的日志在 GBK 控制台触发 `UnicodeEncodeError`，干扰真实故障定位。

已处理：控制台流在不可编码字符处使用可逆转义回退；UTF-8 文件日志不降级。
